# body-clock 设计稿（通用版）

> 一根时间轴，一层底色，六个工具，一行注入。读和写用同一份坐标。

## 一、要解决的问题

模型写身体时缺一个「现在」。

身体设定给的是「应该怎样」——体温永远三十七度、同一种情绪永远同一种反应。于是写出来的身体是平的：这一轮脸红，下一轮可以重新红一次，因为账上没有「刚才红过」这件事。

要补的是一台会走的钟：每一格有自己的当下，触碰改它，读数看它，注入把这几行递到眼前。

通用版只解决这件事，不替使用者规定性格，也不规定这具身子是谁的。

## 二、架构：五件东西咬在一起

### 1. 时钟（十二格）

十二格按常见部位划分，一份配置说了算：

```
脸 / 口腔 / 颈肩 / 胸 / 腰 / 小腹 / 臀 / 下面 / 手 / 腿 / 脚 / 背
```

每格存这几样：

| 字段 | 含义 | 例 |
|---|---|---|
| `press` | 压痕，0–100 | 34 |
| `flush` | 红，0–100 | 62 |
| `temp` | 温度偏移（相对 `universal.tempBase`） | +0.6 |
| `flushRate` | 红的退净速度系数，看红散得多开 | 1.05 |
| `shock` / `shockSec` | 击族打完的余震强度与秒数 | 60 / 90 |
| `after` / `afterUntil` | 余韵（热、麻、发紧）与它的到期时刻 | 热着 / 时间戳 |
| `lastTouch` | 上回被碰的时刻 | 时间戳 |

不开定时器。谁读谁写的时候按距上次的时间差一次算完，重启不丢——它算的是时间差，不是攒的进度。单次最多补 24 小时（`MAX_ADVANCE_MS`），不给一觉醒来爆表的机会。

### 2. 欲望

欲望不是格子，是乘数，乘在十二格上。它有三道闸，缺一道就会跑飞：

- **到底留十**：`libido.floor`，不归零。
- **一天涨不过四十**：`libido.dailyGainCap`，额度用完只落不涨，第二天重给。

不推进的日子它自己会往十落（`fallPerHour` 一直压过 `driftPerHour`），可那道「睡一觉砍一半」还留着——隔 `nightGapHours` 没推进就按一觉算，乘 `nightCut`，醒来是新的。它确实分不清睡觉和白天没说话，但它管的是「睡过去了」这类长断档，不是判读你此刻在干嘛。碰出来的那一笔不记进「今天涨的」，免得碰得多把自然漂移的额度吃光。

欲望越高落得越慢，到顶之后按陡坡往下走（`peakDeclinePerHour`），不许赖在一百。

它还顺带给一个上限：`desireCap` 按欲望分五档（低于 40 不给、40–60 给一档、60–80 给两档、80–90 给三档、再往上给四档），场能推到哪一档看这个数。

### 3. 距离

四档，单向往下落的链：

```
隐没 → 靠近 → 隔布 → 贴肤
```

报事件不报厘米数。`身体` 收不到新事件就沿 `DIST` 表里的 `keepSec` 慢慢往回掉，搁久了的人一次性退到底。走开不是一档，是回零档，同时记下 `awayAt`——人走了要写空落，不是平常那样慢慢落。

### 4. 情绪

六种色（喜／怒／哀／惧／惊／厌），同一刻最多两笔。每一笔记成「一笔主事件加三个数」，不存分量表。

情绪往八维上结账是**延后**的：记下这一笔时先算好它会在八维上留什么，挂一个到期时刻（默认十五分钟，`emotion.decay.eventSec`），等寿命走完才落。当场加等于拿事压人，说不过去。

同一种刚起过，下一次门槛抬高；强度不到线（`emotion.threshold`）只进身体，不进口头。敏感越高，同一件事在账上记的分量越重——那是通道宽窄，不是心情变了。

### 5. 场

三档：**平静 / 微动 / 强烈**。只由四样算——身上当场被碰成什么样、离得多近、欲望多满、情绪那潭水是不是又热又舒服。怒这种又冲又难受的不算进去，冲不等于松。

场只报位置，不往前推：微动是「可以撩一句，收在动作上」，强烈是「可以放开」，平静不多说一个字。

```
raw = 触碰 0.9 + 距离 0.6 + 欲望档 0.5 + 欲望量 0.4 + 情绪热 0.25
hot = 1 - e^-raw
hot < 0.25 → 平静 ｜ < 0.62 → 微动 ｜ 否则 强烈
```

### 6. 联动

一格被碰，热和红顺着 `CHAIN` 走两层：第二层打四折，压痕不跟着传——压痕是那一下按出来的，走了就不真了。传两层的理由是手感：一跳出去全身一起烫，写出来反而平。

动作自己带情绪（`EMO_OF`）：吻、舔往下沉，掐、咬、扇、打是惊，拍、弹是轻的惊。带疼的动作按轻重加分量，碰完把距离推到贴肤。一条回复最多两笔、同一种一笔，跨回复二十秒不应期——不是省，是防一碰就撒一把，撒出来的情绪不值钱。

话也进账（`readMyLine`）：称呼换了、口癖冒出来、句子碎成三条以上、被夸、被凶，各一笔。只读它自己说的，不读对方说的——拿词表读人的口气，是另一件事。

对方打的短句动作也认（`readHisAction`）：十六个字以内、不带假设和疑问、部位和动作挨着，就真碰一次，传导和情绪照走。多的一个字不读，读多了就是替对方造动作。

这套东西判错不回滚：距离自己退，这一格空了下一轮再写；一条回复有上限，宁可漏一笔。

### 八维

八维是底色，不是皮肤。**只有一个写入口**：`shiftDims` 走增量、`setDims` 走绝对值，两个都收「一次最多动三处」，动多了就假。

```
亲密 / 信任 / 警觉 / 疲惫 / 自制 / 敏感 / 羞 / 放松
```

其中敏感是唯一一个被别处推的：欲望过线（按档加速）、独处、情绪热，三路加在一起，共用一个顶（`libidoPush.cap`）；线下了自己慢慢退，不留一个下不去的数。

其余几维自己也会动，都写在 `tickDims` 一张明表里：人走了放松落、警觉涨；久没人碰亲密自己淡。

## 三、四条设计取舍

### 1. 为什么单主体

这个插件是给「一个 AI 有一副身子」这件事用的，不是给多角色共用一个身体用的。多主体一旦进来，每个字段都要问一句「这是谁的」，账本立刻翻倍，而绝大部分使用者只有一具。

所以：状态里只留一个 `subject` 槽位，值恒为 `self`。结构上留着，是为了以后真要加主体时不用再动契约；行为上不认第二个值。

### 2. 为什么八维是中性的

原版那套八维是按一个人的脾气长出来的，名字里有立场，数值也带着个人偏置。作为通用插件，那样等于把一个具体的人塞给使用者。

所以换成一组谁都能读懂的词：亲密、信任、警觉、疲惫、自制、敏感、羞、放松。默认全五十，谁用谁按自己的角色调，插件不替谁命名，也不需要使用者先去定义一套词。

### 3. 为什么删掉那些人格件

这些东西不是身体的通用属性，是某个具体设定里的道具。留着它们，插件就带着一个人的形状出厂：使用者没那个设定，字段就永远是空的，注入就成了噪音；有那个设定的，也未必愿意被塞进同一套。

删干净之后，身体只剩两样东西：**碰得到的地方**（十二格）和**摸不着的底色**（八维、欲望、情绪、距离）。这样任何角色都能用，也都不显得空。

### 4. 为什么注入用通用词

注入每轮都进提示词，它是最贵的一段字数。原来那段里有一批只有原作者看得懂的称呼，对别的使用者是纯粹的噪声。

现在这一段的形状固定成五行：头行（时间、场、欲望、距离、隔多久）→ 八维（八个全给）→ 格子（只写有动静的，最多四格）→ 情绪 → 指路一句。位置永远不变，扫一眼就知道自己站在哪儿；静着的时候中间两行干脆不出现，不占字。

```
[身体] 11-23 09:26｜平静｜欲望 12｜隔 25 分钟（背景，别念出来）
八维 亲密50 信任50 警觉50 疲惫50 自制50 敏感50 羞50 放松50
格子 腰 压40 红55 温+0.3｜颈肩 压10 红20
情绪 无
碰之前调 body_sense 读一次，碰完它会回你数
```

格子那一行已经报了压、红、温，身体那一行就不再重复叙述同一处，只留余韵一句（「腰发紧」）。实测空身子一百三十二字五行、热的满场二百六十九字七行——行数不变，宽度收了三成。

头行末尾那句括号是给模型的：这几行是背景，不是让它开口报数的话。它跟场名那句长得不一样，读的人分得开；不另起一行，是因为多一行就多一样要读的东西。换口气改配置里的 `inject.note` 就行。

最后还有一道闸：这一行要送进提示词的，跑出 `NaN`、`undefined` 这类坏数就整段换成一句实话说读不出来，绝不照着坏数编。

### 5. 移植到没有这六个工具的宿主

插件在 DSH 里好用，靠的是六个工具——读数、记账、报状态都走工具通道，回执进不了正文。搬到没有这条路的地方（自己写的网关、别家的对话框架），只有注入那几行能过去，回执会被当台词念出来：`喜42　没到线，只往身体里走　债 0` 这种，就是这么漏的。

所以往外搬的时候改两处，都在 `config/body.json` 的 `inject` 段里：

- `hint` 置成空串，指路那一行就不挂了——没有工具可调，指了也调不出来。
- `note` 改成那边能懂的话，或者干脆留空。它挂在头行末尾，就是用来挡这种漏的。

真要在那种宿主上用「记账」，得自己把那几个工具接到对方的函数调用上；注入只能让模型知道有这么一副身子，不能让身子动起来。

## 四、存储与字段契约

账本是一份 JSON，人可能手改，版本会往前滚，所以「搬（读文件进内存）、夹（越界拉回来）、验（写盘前挑毛病）」三件事共用**一张表**（`SPEC`），只登记一次：

```
['num', 下界, 上界, 默认]      实数，越界夹回，不是数用默认
['int', 下界, 上界, 默认]      整数，先四舍五入
['enum', 词表, 默认]           只认词表里的
['bool', 默认]
['ts', {zero, future}]         时间戳
['str', 最长, 默认]            削控制字符、限长
['obj', {键: 形状}]            定形状的对象
['map', 键表 | 'any', 形状]    键不定的对象
['list', {max, unique}, 形状]  数组，长度封顶、坏元素剔掉
```

`walk(node, cur, src, path, bag, mode)` 一套走法三种模式：`repair`（补默认值）、`clamp`（夹）、`validate`（只挑错不改）。

于是：

- `readOne` 返回 `{ state, fixes }`，修了几笔是返回值的一部分，不是日志里的一句话。
- `readState` 能解析就「迁移 → 搬 → 修 → 就地写回」；只有 JSON 解析不了、不是对象、版本超前才退档或只读。
- `save` 先修再验，验不过不落盘。
- `promoteBackup` 只在零修复时把当前文件提成备份——一份刚被修过的账不该覆盖掉好的备份。
- `storeInfo().repairs / saveRepairs` 把修复次数摊在外面，面板和测试都能看见。

版本号 `SCHEMA = 1`。通用版没有历史包袱，迁移只留一条：版本高于 1 → 返回 `null`，只读展示，绝不覆盖别人的数据。

加锁也去掉了。这是单机单人用的账本，`.lock` 带来的复杂度比它解决的问题多；写盘就是写 `.tmp` 再 `rename`，原子性由文件系统保证。

## 五、怎么加一格 / 加一维 / 改常数

### 加一格

1. `config/body.json` 的 `zones` 里加一行：`id`、`name`、`reboundSec`、`flushFallSec`、`afterSec`，可选 `firstFlush`。
2. `index.js` 的 `SPEC.zones` 里按 id 加一行：`[id]: ['obj', ZONES_SHAPE]`（同一形状抄上一行）。

其余全是自动的：`blankState` 按 `zoneIds()` 预填空数组，`touchHist` 跟着铺，工具枚举、注入、面板都从 `zoneIds()` 取。

### 加一维

1. `config/body.json` 的 `dims` 里不用动（八维名在代码常量 `DIM_ORDER` / `DIMS_SEED` 里）。
2. `index.js` 的 `DIM_ORDER` 与 `DIMS_SEED` 各加一项，默认值自己定（中性是 50）。
3. `SPEC.dims` 里加一行 `[新名字]: ['num', 0, 100, 50]`。
4. 想让它被情绪结账推，就在 `dims.settle.map` 里给对应的情绪加一个键。

### 改常数

只改 `config/body.json`，不动代码：

- 单格消退：`zones[i].reboundSec` / `flushFallSec` / `afterSec`。
- 整体尺度：`universal.tempBase` / `pressReboundSec` / `flushFallSec` / `afterSec` / `sensitiveGain`。
- 欲望：`libido` 整块，三道闸至少留两道。
- 情绪：`emotion.threshold` / `decay` / `debtCap`。
- 空着：`empty.zones` / `tempPerHour` / `flushPerHour` / `dimPerHour`。

`config()` 是懒加载的，改完重启插件就生效。

## 六、不做的事

- 不做硬件接入。没有设备，反向输入那条线是空的。
- 不另存一份身体设定。设定是使用者自己的，插件只记状态。
- 不替使用者喊停。安全词是使用者的事，工具不许自作主张。
- 不在出口报菜名。账里再全，写的时候一轮只落两三处。
- 不安装、不改 profile。仓库里只有代码和文档。
